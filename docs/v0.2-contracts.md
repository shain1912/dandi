# Dandi v0.2 구현 계약서 (병렬 개발 기준)

이 문서는 PRD v0.3 15장(F-31~F-58)을 여러 에이전트가 동시에 구현하기 위한 **인터페이스 계약**이다. 각 영역 담당자는 자기 파일만 수정하고, 다른 영역은 아래 계약(함수 시그니처·HTTP API·JSON 형식)을 믿고 호출한다. 계약을 바꿔야 하면 바꾸지 말고 최종 보고에 적는다.

근거: `planning/PRD.md` 14·15장, `planning/벤치마크_AI연결_프로젝트키_스킬_전자책_20260928.md`.

## 0. 공통 규칙

- Next.js 16.3.6 (App Router). API가 바뀌었으므로 `node_modules/next/dist/docs/`를 먼저 확인한다. `params`/`searchParams`는 Promise, `cookies()`/`headers()`는 async, 미들웨어는 `src/proxy.ts`.
- 저장소: `src/lib/db.ts`의 `readDb()`(스냅샷), `mutate(fn)`(직렬화된 읽기-수정-쓰기, 바뀐 것이 없으면 쓰지 않음), `newId(prefix)`, `nowIso()`, `DATA_DIR`, `UPLOAD_DIR`, `BLOB_DIR`. 타입은 `src/lib/types.ts`(이미 모든 컬렉션 정의됨).
- 세션: `src/lib/session.ts` — `getCurrentUser()`, `isTeacher()`, `requireTeacher()`, `requireAdmin()`, `AuthError`, `ensureUser()`, `displayName()`, `writeAudit(db, actor, action, target, detail)`.
- 에이전트·CLI 인증: `src/lib/agent-auth.ts` — `authenticateAgent(req)`(dd_cli_ CLI 토큰과 dd_mat_ OAuth 접근 토큰 모두 처리, 교사·관리자만 통과), `apiError(status, code, message, hint?)`, `agentAuthError(auth)`.
- 비밀값: `src/lib/tokens.ts` — `generateSecret("cli"|"sk"|"mat"|"mrt"|"dev")` → `{secret, hash, prefix}`, `hashSecret`, `bearerToken(req)`. 원문은 발급 응답에서 한 번만 돌려주고 해시만 저장한다.
- 주소: `src/lib/origin.ts` — `hubOrigin()`(서버 컴포넌트), `hubOriginFromRequest(req)`(라우트 핸들러), `siteOrigin(hub, label)`, `safeNextPath(next)`.
- 개인정보: `src/lib/pii.ts`(`scanPII`, `hasPII`, `maskPII`, `maskFields`), `src/lib/text.ts`(`normalizeNewlines`, `urlHasPII`). 저장하는 모든 자유 입력 텍스트는 길이 확인 → 마스킹 순서로 처리한다. 폼은 `PiiInput`/`PiiTextarea`와 `submitWithoutReset`(`src/components/submit-without-reset.ts`, `<form action={action} onSubmit={(e) => submitWithoutReset(e, action)}>`)을 쓴다.
- 기존 미니앱: `src/lib/apps.ts` — `createApp(input: NewAppInput, author)` → `{ok,value:MiniApp}|{ok:false,error}`, `validateNewApp`, `canViewApp`, `approveApp`. 사이트 publish는 이 함수로 미니앱을 만든다.
- **새 HTTP API의 오류 형식**: `{ "error": { "code": "<snake_case>", "message": "<한국어>", "hint": "<다음에 할 일, 선택>" } }`. 성공 응답은 평범한 JSON 객체. 인증 실패는 401 + `WWW-Authenticate: Bearer`.
- UI 문구는 한국어 합니다체("~하십시오"), 느낌표·이모지 없음. 디자인 최소화: `globals.css`의 기존 클래스만(.list .badge .badge.warn .filter .muted .notice .error form.stack .field .table-wrap iframe.app-frame .button .button.primary), 새 전역 CSS·CSS 프레임워크 금지.
- 기존 v0.1 기능과 E2E(`e2e/demo.e2e.mjs`)를 깨지 않는다. 단, AI 키(F-20→F-32) 관련 E2E 7단계는 프로젝트 키 방식으로 바뀐다(integrator가 고친다).
- 검증: `npx tsc --noEmit`, `npx eslint <내 파일>`, `npm test`. **next build / next dev / npm install 금지**(integrator가 한다). 필요한 패키지는 이미 설치됨: `mcp-handler@2.2.0`, `@modelcontextprotocol/server@^2`, `zod@^4`, `fflate`, `react-pdf@^11`. 로직 확인이 필요하면 임시 `DANDI_DATA_DIR`로 node 스크립트를 쓴다(프로젝트 `data/`는 건드리지 않는다).

## 2. 사이트 호스팅 계약 (A가 구현, B·C가 호출)

### 2-1. 주소
- 공개(live): `siteOrigin(hub, slug)` → 로컬 `http://<slug>.localhost:3000/`
- 미리보기: `siteOrigin(hub, `${slug}--${previewToken}`)` → `http://<slug>--<token>.localhost:3000/` (token: 소문자·숫자 10자, 추측 불가, 해당 배포만 보여 줌, `X-Robots-Tag: noindex`)
- slug: `^[a-z0-9](?:[a-z0-9-]{1,28}[a-z0-9])$`, `--` 금지, 전역 고유, 예약어(www, api, admin, hub, mcp, static 등) 금지. 없으면 제목 로마자화 대신 `site-<6자>` 무작위.
- `src/proxy.ts`: Host가 `*.localhost[:port]`(또는 `*.${SITES_DOMAIN}`)이면 `/site-serve/<label>/<path>`로 rewrite한다(주의: Next.js는 `_`로 시작하는 폴더를 라우팅하지 않으므로 `_site` 같은 이름은 쓸 수 없다). **`/site-serve/**` 라우트는 요청 Host가 사이트 호스트일 때만 응답하고, 허브 호스트로 직접 들어온 요청은 404로 막는다**(업로드된 HTML이 허브 origin에서 실행되면 교사 세션을 쓸 수 있기 때문). `matcher`는 `/site-serve`를 제외하지 않는다. 세션 쿠키 발급 로직은 허브 호스트에만 적용한다. 사이트 응답에는 `Set-Cookie`를 넣지 않는다.
- 사이트 응답 헤더: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Content-Security-Policy: frame-ancestors <hub origin>`, `Cache-Control: no-store`(v0.2). 디렉터리 요청은 `index.html`. 없는 파일은 404 페이지.
- live 주소는 사이트가 publish되고 연결된 미니앱이 공개 상태일 때만 서빙한다. 승인 대기(approvalStatus "pending")면 403 "학교 내부 승인 대기 중" 안내 페이지를 준다.

### 2-2. 업로드 한도·검증 (`src/lib/sites.ts`에서 export)
```ts
export const SITE_LIMITS = { totalBytes: 20 * 1024 * 1024, fileCount: 1000, fileBytes: 5 * 1024 * 1024 };
export const SITE_ALLOWED_EXT = ["html","htm","css","js","mjs","json","txt","md","svg","png","jpg","jpeg","gif","webp","ico","avif","woff","woff2","ttf","mp3","mp4","webm","wasm","xml","csv","pdf"];
```
- 루트 `index.html` 필수. 경로: 슬래시 구분 상대 경로, `..`·절대경로·역슬래시·제어문자 금지, 세그먼트가 `.`으로 시작하면 거부(`.env`, `.git` 등). 소문자 변환 없이 그대로 저장.
- 텍스트 파일(html/css/js/mjs/json/txt/md/svg/xml/csv)에 비밀값 패턴(`dd_cli_`, `dd_sk_`, `dd_mat_`, `sk-[A-Za-z0-9]{20,}`, `service_role`, `-----BEGIN .*PRIVATE KEY-----`)이 있으면 finalize를 거부(422 `secret_detected`, hint에 파일 경로). 개인정보(`scanPII`) 패턴은 거부하지 않고 finalize 응답의 `warnings`에 경로와 종류를 담는다.

### 2-3. HTTP API (인증: `authenticateAgent` — CLI 토큰 또는 OAuth 접근 토큰. 웹 폴더 업로드 화면은 서버 액션이 같은 lib 함수를 직접 부른다)

1. `POST /api/sites/deploys`
   요청 `{ "siteId"?: string, "slug"?: string, "title"?: string, "projectId"?: string, "files": [{ "path", "size", "sha256" }] }`
   - siteId가 없으면 새 사이트를 만든다(slug 지정 가능, projectId 없으면 교사의 기본 프로젝트 — `ensureDefaultProject(user)` from `src/lib/projects.ts`).
   - 응답 201 `{ "deployId", "siteId", "slug", "upload": ["<서버에 없는 파일 경로>", ...] }`
2. `PUT /api/sites/deploys/{deployId}/files?path=<encodeURIComponent(path)>` 본문=파일 원본 바이트 → 204. 크기·sha256 불일치면 400 `hash_mismatch`.
3. `POST /api/sites/deploys/{deployId}/finalize` → 200 `{ "siteId", "deployId", "slug", "previewUrl", "status": "preview", "warnings": [{ "path", "kind", "message" }] }`. 빠진 파일이 있으면 409 `missing_files`(hint에 경로).
4. `POST /api/sites/{siteId}/publish` 요청 `{ "deployId"?: string(기본: 최신 ready 배포), "title", "description", "schoolLevels": [...], "category", "privacyCheck": { "collectsStudentData", "storageLocation", "retention", "externalTransfer", "needsSchoolApproval" } }`
   → 200 `{ "appId", "appUrl": "<hub>/apps/<appId>", "liveUrl", "approvalStatus": "not_required"|"pending" }`. 검증 오류는 422 `invalid_publish`(message는 `validateNewApp` 메시지). 이미 publish된 사이트면 live 배포만 바꾸고 기존 미니앱 정보를 갱신한다(새 미니앱을 만들지 않는다).
5. `GET /api/sites` → `{ "sites": [{ "id","slug","title","projectId","liveUrl"|null,"previewUrl"|null,"appId"|null,"approvalStatus"|null,"updatedAt" }] }` (내 사이트)

## 3. CLI·device 로그인 계약 (B가 구현)

### 3-1. device code API
- `POST /api/cli/device/start` 요청 `{ "client"?: string, "hostname"?: string, "os"?: string }` → 200 `{ "device_code", "user_code": "WDJB-MJHT", "verification_uri": "<hub>/device", "verification_uri_complete": "<hub>/device?code=WDJB-MJHT", "expires_in": 600, "interval": 5 }`
  - user_code: `BCDFGHJKLMNPQRSTVWXZ`에서 8자, `XXXX-XXXX`, 입력은 대소문자·하이픈 무시. device_code는 `generateSecret("dev")`, 해시만 저장. 만료 600초, 1회용.
- `GET /device?code=...` (웹): 교사 세션 필수, 아니면 `/login?next=<현재 경로>`로 redirect. 큰 코드, "AI 대화창·터미널에 보이는 코드와 같나요?", 요청 도구·컴퓨터 이름·OS·요청 시각·남은 시간·권한("사이트 올리기·허브 등록·스킬 게시")·경고문("직접 AI에게 Dandi 로그인을 시킨 경우에만 승인하십시오. 웹사이트나 다른 사람이 이 코드를 보냈다면 거부하십시오."), [승인]/[거부]. 코드 입력칸도 제공(code 없이 열었을 때).
- 승인·거부는 서버 액션(교사 세션 재확인, 감사 로그 `cli.device.approve`/`cli.device.deny`).
- `POST /api/cli/device/token` 요청 `{ "device_code" }` → 대기 400 `{ "error": "authorization_pending" }`, 너무 잦음 400 `{ "error": "slow_down" }`, 거부 400 `{ "error": "access_denied" }`, 만료 400 `{ "error": "expired_token" }`, 성공 200 `{ "token": "dd_cli_...", "user": { "name", "role", "schoolLevel" } }`(RFC 8628 형식이라 error는 문자열). 성공은 한 번만, 이후 `consumed`. 발급 토큰은 `cliTokens`에 저장(감사 `cli.token.issue`, detail에 client·hostname).

  `{"ok":true,"status":"pending","user_code":"WDJB-MJHT","verification_uri":"http://localhost:3000/device","verification_uri_complete":"http://localhost:3000/device?code=WDJB-MJHT","expires_in":600,"next_step":"npx -y http://localhost:3000/dandi-0.2.0.tgz login --wait --json","agent_instructions":"Show verification_uri_complete and user_code to the user exactly as given, ask them to approve in the browser, then run next_step. Repeat next_step while status is pending."}`
- 설정: `~/.dandi/config.json`(0600, 디렉터리 0700), `DANDI_CONFIG_DIR`, `DANDI_TOKEN`, `DANDI_HUB` 유지. 토큰은 어떤 출력에도 넣지 않는다.
- 배포물: `scripts/pack-cli.mjs`가 `cli/`를 `npm pack` 해서 `public/dandi-<version>.tgz`로 둔다. `package.json` scripts에 integrator가 `"pack:cli"`, `"predev"`, `"prebuild"` 연결. 허브에서 실행: `npx -y <hub>/dandi-0.2.0.tgz <명령>`. `next_step` 등 CLI가 안내하는 명령은 현재 허브 주소와 버전으로 만든 이 형식을 쓴다(환경변수 `DANDI_NPX` = 실행 접두어를 덮어쓸 수 있음).

## 4. MCP 도구 계약 (C가 원격용으로, B가 stdio용으로 같은 이름·의미로 구현)

| 도구 | 입력 | 동작 |
|---|---|---|
| `dandi_whoami` | 없음 | 로그인한 교사 이름·역할·학교급 |
| `dandi_privacy_questions` | 없음 | 셀프점검 5문항 원문과 답 형식(에이전트가 교사에게 그대로 물을 문장) |
| `dandi_deploy_files` | `{ files: [{ path, content, encoding: "utf8"|"base64" }], siteId?, slug?, title? }` (합계 5MB 이하) | 2-4 `deploySiteFiles` → previewUrl, warnings |

원격 MCP(`<hub>/mcp`)는 `authenticateAgent`와 같은 규칙으로 dd_mat_(OAuth)과 dd_cli_(헤더 직접 지정) 토큰을 모두 받는다. 인증이 없으면 401 + `WWW-Authenticate: Bearer resource_metadata="<hub>/.well-known/oauth-protected-resource/mcp"`.

## 5. OAuth (C가 구현)
- `GET /.well-known/oauth-protected-resource` 및 `/.well-known/oauth-protected-resource/mcp` → `{ "resource": "<hub>/mcp", "authorization_servers": ["<hub>"], "bearer_methods_supported": ["header"], "scopes_supported": ["dandi"], "resource_name": "Dandi" }`
- `GET /.well-known/oauth-authorization-server` → issuer `<hub>`, `authorization_endpoint` `<hub>/oauth/authorize`, `token_endpoint` `<hub>/oauth/token`, `registration_endpoint` `<hub>/oauth/register`, `response_types_supported ["code"]`, `grant_types_supported ["authorization_code","refresh_token"]`, `code_challenge_methods_supported ["S256"]`, `token_endpoint_auth_methods_supported ["none"]`, `scopes_supported ["dandi"]`, `authorization_response_iss_parameter_supported true`.
- `POST /oauth/register`(RFC 7591, 공개 클라이언트) → 201 `{ client_id, client_name, redirect_uris, token_endpoint_auth_method: "none", grant_types, response_types }`. redirect_uri는 `http://localhost:*`/`http://127.0.0.1:*`(루프백) 또는 https만 허용.
- `GET /oauth/authorize`(동의 화면, 교사 세션 필수 → `/login?next=`), PKCE S256 필수, state 그대로 반환, `iss` 파라미터 포함. 허용·거부는 서버 액션. 코드 10분·1회용.
- `POST /oauth/token`(application/x-www-form-urlencoded): authorization_code(code, redirect_uri, client_id, code_verifier) → `{ access_token: "dd_mat_...", token_type: "Bearer", expires_in: 3600, refresh_token: "dd_mrt_...", scope: "dandi" }`; refresh_token → 새 access + 새 refresh(이전 refresh 폐기, 재사용 감지 시 해당 연결 전체 폐기). 오류는 RFC 6749 `{ error, error_description }`.
- 연결된 AI 도구 목록·폐기: `/studio/cli` 화면은 integrator가 링크만 달고, C가 `/oauth/connections`(교사용 목록·폐기) 페이지를 만든다.

## 6. 스킬 레지스트리 (F가 구현, B·C·D가 호출)
- 게시 API(`authenticateAgent`): `POST /api/skills` 요청 `{ "files": [{ "path", "contentBase64" }], "title"?, "schoolLevels"?, "compatibility"? }` → 201 `{ "name", "version", "status": "approved"|"pending_review", "findings": [...], "url": "<hub>/skills/<name>" }`. 검증 오류 422 `invalid_skill`.
- `GET /api/skills?q=` → `{ "skills": [{ "name","title","description","installs","latestVersion","hasScripts","status","installCommand" }] }` (공개 승인 스킬만)
- `GET /api/skills/{name}` → 상세 + `skillMd`(SKILL.md 본문)
- 설치 소스: `/.well-known/agent-skills/index.json`(Agent Skills Discovery v0.2.0, archive + `sha256` digest) 및 구 경로 `/.well-known/skills/index.json`. vercel-labs/skills CLI 소스(`src/providers/wellknown.ts`)를 읽어 실제로 `npx skills add <hub> --skill <name>`가 되게 만든다. 설치 시 `installs`를 센다.
- 설치 명령 문자열(목록·상세·CLI·MCP 공통): 10장의 `skills@latest` 명령(다섯 도구)
- `src/lib/skills.ts` export: `listPublicSkills(q?)`, `getSkill(name)`, `publishSkill(user, files, meta)`, `skillInstallCommand(hub, name)`.

## 9. 구현 후 바뀐 계약 (QA 두 차례 반영, 2026-09-29)

- **CLI 배포 이름**: `public/dandi-<버전>-<해시8>.tgz`(내용이 바뀌면 이름이 바뀜). 최신 이름은 `/dandi-latest.json`. 예전 해시 파일은 지우지 않고, 해시 없는 `dandi-0.2.0.tgz`는 더 만들지 않는다. 런북·/connect·CLI의 next_step은 모두 최신 이름을 쓴다.
- **셸별 접두어**: Windows에서 `MSYSTEM`이 있으면(Git Bash) `npx`, 없으면(PowerShell·cmd) `npx.cmd`, 그 밖은 `npx`. `--json` 출력은 UTF-8이며, Windows PowerShell·cmd(또는 `DANDI_JSON_ASCII=1`)에서만 한글을 `\uXXXX`로 이스케이프한다.
- **publish 결과**: `{ appId, appUrl, liveUrl, previewUrl, approvalStatus: "approved"|"not_required"|"pending", liveVersion: "updated"|"kept_until_approval", message }`. 승인된 앱을 같은 답으로 다시 게시하면 승인이 유지되고(approved) 바로 공개된다. 답이 바뀌어 다시 승인이 필요하면 새 버전은 `Site.pendingDeployId`에 두고 공개 주소는 이전 승인 버전을 계속 보여 준다(승인 시 `approveApp`이 옮김). CLI·MCP는 서버 message를 그대로 전달한다.
- **프로젝트 이동**: `POST /api/sites/deploys`의 `projectId`는 새 사이트를 만들 때만 적용된다. 기존 사이트는 `moveToProject: true`(CLI `deploy --project <id>`, 웹 "프로젝트 바꾸기")일 때만 옮기고, 응답의 현재 `projectId`를 dandi.json에 되써 둔다.
- **CLI 추가 플래그·필드**: `login --force`, `deploy --new-site | --project <id> | --allow-source`, `help --json`, 응답의 `notes`(정보)·`warnings`(개인정보·제외 파일)·`next_step_template`(실행 전에 채울 명령)·`done`(로그인 완료 여부)·`saved_answers`(다시 게시할 때 확인할 기존 답).
- **종료 코드 추가**: 2 = 사용법·폴더 없음·index.html 없음·dandi.json 인코딩 오류(`manifest_encoding`), 20 = 업로드 거부·`source_folder`·`site_not_found`(계정 확인 먼저), 21 = 셀프점검·등록 정보 누락(`missing`은 교사에게 묻고, `invalid_format`은 다시 묻지 않고 고친다).
- **보안**: 사이트 파일 해시는 올린 사람 기준으로만 "이미 있음"으로 본다(다른 교사의 파일 존재·내용 노출 방지). `X-Forwarded-*`는 `TRUST_PROXY=1`일 때만 믿는다. 허브 화면은 `frame-ancestors 'self'`, 승인 화면은 `'none'`.

## 10. 이름·문서·URL 한 번 흐름 (2026-09-29, PRD F-60~F-62)

- **이름**: 서비스 Dandi, CLI 명령 `dandi`(npm 패키지 이름은 `dandi`가 이미 있어 `dandi-cli`), 설정 `~/.dandi`·`DANDI_CONFIG_DIR`, 프로젝트 파일 `dandi.json`, 토큰 접두어 `dd_`.
- **문서 분류**: 사람이 읽는 문서 `/docs`, `/docs/<문서>`(예전 `/guide`는 `/docs`로 영구 이동). AI가 읽는 원문 `/llms.txt`(런북), `/llms-full.txt`(레퍼런스), `/docs/index.md`, `/docs/<문서>.md`(`/docs/md/<문서>`로 rewrite, 세션 쿠키 없음). 같은 원문(`src/lib/docs/pages/*`)에서 두 형식을 만든다.
- **URL 한 번 흐름**: 런북 1~4단계(whoami → 필요하면 브라우저 승인 로그인 → 빌드·deploy → 미리보기)는 묻지 않고 진행한다. 요청에 제목·설명·학교급·분류·①~⑤가 모두 있으면 다시 묻지 않고 publish한다.
- **스킬 설치 명령**(목록·상세·CLI·MCP·/connect 공통): `npx -y skills@latest add <hub>/.well-known/agent-skills/<name> --skill <name> -a claude-code -a cursor -a codex -a antigravity-cli -a grok --copy`. `-a grok`은 skills 1.7.0부터 받으므로 `@latest`로 고정한다. 설치 위치: claude-code `.claude/skills`, cursor·codex·antigravity `.agents/skills`, grok `.grok/skills`.
- **CLI `setup`**: 위 명령으로 `dandi-deploy` 스킬을 현재 폴더(또는 `-g`)에 설치하고, 보낼 문장(`prompt`, `prompt_with_answers`)을 돌려준다.
- **시드 스킬 `dandi-deploy` 1.3.0**: 허브 주소·CLI 접두어를 내보낼 때 넣는 템플릿(`{{HUB}}`, `{{CLI}}`). headless 도구(codex exec, agy -p, grok -p)는 미리 로그인하고 요청에 답을 적도록 안내한다. 정적 사본 `/downloads/SKILL.md`는 허브 주소를 HUB로 적은 같은 흐름이다.
