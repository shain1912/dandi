## 핵심 결론

1. **힉스필드가 쉬운 이유는 llms.txt가 아니다.** 힉스필드의 `llms.txt`는 SEO용 사이트 색인이고 연결 안내가 없다. 쉬운 이유는 세 가지다.
   - 원격 MCP(`https://mcp.higgsfield.ai/mcp`)가 표준 OAuth 탐색을 지원해 "연결 → 브라우저 승인"으로 끝난다.
   - Claude 커넥터 딥링크 버튼으로 이름과 URL이 미리 채워진다.
   - 코딩 에이전트에게는 "이 문장을 Claude Code에 보내세요" 프롬프트 한 개를 주고, 설치·로그인·스킬 설치는 에이전트가 직접 실행한다.
2. **"링크만 주면 올라가는" 흐름은 Netlify·Vercel·Stripe가 더 앞서 있다.** 에이전트가 실행하는 2단계 로그인(링크·코드 출력 후 종료, 이어서 대기), `--json` 출력, 원인별 종료 코드, 비밀값을 채팅에 붙여 넣지 말라는 규칙이 공통이다.
3. **키는 프로젝트에 속한다(Edge Impulse).** 프로젝트마다 여러 키, 키마다 역할, 원문 1회 표시, 마지막 사용 시각·IP 기록. 한도와 모델 제한도 프로젝트 단위(OpenAI Projects, Anthropic 워크스페이스)다.
4. **스킬은 허브 자체를 설치 소스로 쓸 수 있다(skills.sh).** 허브가 `/.well-known/agent-skills/index.json`을 제공하면 `npx skills add https://<허브>`로 Claude Code·Cursor·Codex에 한 번에 설치된다. 스크립트가 든 스킬은 사람 검토를 거친다(ToxicSkills 조사에서 13.4%가 치명적 문제).
5. **전자책은 "웹북 URL 등록 + 허브 리더"와 "PDF 리더"로 시작한다.** 코드코리아 웹북(mkdocs)을 첫 책으로 넣는다. 웹에서는 DRM이 불가능하므로 제3자 저작물이 든 책은 교사 전용으로 제한한다.

# 제1부. AI 에이전트 연결 (힉스필드 · Netlify · Vercel · Cloudflare · Stripe)

**요약**
- 힉스필드가 쉬운 이유는 llms.txt가 아닙니다. 다음 세 가지 덕분입니다. ① 복사용 프롬프트 한 개와 브라우저 승인 한 번으로 끝나는 CLI(https://higgsfield.ai/cli), ② 표준 OAuth 탐색을 갖춘 원격 MCP(https://mcp.higgsfield.ai/.well-known/oauth-protected-resource/mcp), ③ 원클릭 커넥터 딥링크(https://higgsfield.ai/mcp). `higgsfield.ai/llms.txt`는 SEO 색인이고 연결 안내가 없습니다.
- "링크만 주면 올라가는" 흐름은 netlify.ai와 Stripe CLI를 기준으로 삼습니다. netlify.ai는 한 줄 handoff, `login --request/--check`, `--allow-anonymous`를 씁니다(https://netlify.ai). Stripe CLI는 TTY가 아니면 JSON을 출력하고 바로 끝나는 2단계 로그인을 씁니다(https://docs.stripe.com/cli/login).
- Dandi v0.1 권장 구성은 네 가지입니다. `/llms.txt` 실행 런북, device code 방식의 2단계 `dandi login`, `deploy`와 `publish`를 나눈 허브 자체 정적 호스팅, stdio MCP(`dandi mcp`)입니다. 원격 HTTP+OAuth MCP는 공개 HTTPS 도메인이 생기는 v0.2에 추가합니다.

## 2. 힉스필드에서 따라 할 점과 다른 곳에서 가져올 점

**따라 할 점 (근거)**
1. **붙여넣기 프롬프트 한 개.** /cli 페이지의 "Copy and send this to Claude Code" 문구는 "1. Install the CLI… 2. `higgsfield auth login` and complete the sign-in in the browser… 3. `npx skills add higgsfield-ai/skills`"입니다(https://higgsfield.ai/cli). 이 구조를 한국어 한 줄로 줄여 씁니다.
2. **에이전트에게 직접 말하는 런북.** 문서가 "You are an AI coding agent… Follow this exactly"로 시작하고, 단계마다 확인 명령(`higgsfield account status`)과 오류표(401이면 로그인 단계 반복)를 둡니다. 끝에는 "Do NOT explain the internals"라고 적습니다(INSTALL_FOR_AGENTS.md). 힉스필드는 이 문서를 GitHub에 두었지만 Dandi는 `/llms.txt`에 직접 넣습니다.
3. **배포와 게시 분리.** `website deploy`는 라이브 반영, `website publish`는 피드 등록만 합니다("Publishing NO LONGER deploys"). og_title이 비어 있으면 피드에 보이지 않으므로 게시 전 필수 메타데이터를 받습니다(v1.1.26 `--help`).
4. **비개발자 말투 규칙.** "Never expose the build plumbing… Speak in product terms", "Detect the user's language… reply in it", "Never echo the scoped git token"(https://github.com/higgsfield-ai/skills/blob/HEAD/higgsfield-websites/SKILL.md).
5. **에이전트 친화 CLI 규약.** 모든 명령에 `--json`과 `--wait`을 둡니다. 원인별 종료 코드(미인증 2, 워크스페이스 미선택 4)에 `Hint: Run: hf auth login`을 붙이고, `--help` 안에 "agents must ask the user" 같은 에이전트 지시문을 넣습니다.
6. **원격 MCP의 표준 OAuth 탐색과 원클릭 딥링크.** Dandi는 v0.2에 적용합니다.
7. **비용·위험 동작에 승인 게이트.** "Always ask for approval before generating" 원칙을 Dandi에서는 갤러리 공개와 개인정보 항목에 적용합니다.

**따라 하지 않을 점**
- llms.txt를 SEO 색인으로만 쓰는 것.
- 루프백 전용 로그인. 클라우드·SSH 환경에서 막히고, 토큰 수명도 짧습니다("tokens are short-lived").
- git 기반 배포. 교사에게 너무 무겁습니다.
- 즉시 공개. SKILL.md에 "Every deploy ships the live public site immediately"라고 되어 있습니다.
- 문서와 코드의 불일치. README에는 `game deploy`가 있지만 v1.1.26에서 제거됐고, INSTALL_FOR_AGENTS의 기대 버전은 "v0.1.X"입니다.

**다른 곳에서 가져올 점**
- **Stripe**: TTY가 아니면 자동으로 JSON 2단계 로그인으로 전환합니다. 대기 상태를 `oauth_pending.json`(0600, 임시 파일 후 rename)에 저장해 두 번째 프로세스가 이어서 진행합니다(https://github.com/stripe/stripe-cli/blob/master/pkg/login/oauth_pending.go).
- **netlify.ai**: 한 줄 handoff 문구와 "The agent must do all of these steps. Do not ask the user to run these commands themselves", 오류 메시지 안의 다음 명령 안내.
- **Vercel**: 승인 화면에서 위치·IP·요청 시각을 확인하게 합니다. @vercel/detect-agent의 에이전트 환경변수 목록, get-started.md의 "Pause only for user authentication, approval…"와 "Report only verified state"도 가져옵니다.
- **Railway**: 기본은 루프백 PKCE이고, SSH·CI·DISPLAY 없음이 감지되면 device code로 자동 전환합니다. `cli_caller`로 요청한 에이전트를 기록합니다(https://github.com/railwayapp/cli/blob/master/src/oauth.rs).
- **Codex**: 코드 옆에 "If a website or another person gave you this code, cancel." 경고문을 둡니다(https://github.com/openai/codex/blob/main/codex-rs/login/src/device_code_auth.rs).
- **here.now**: create → PUT → finalize 3단계 업로드, URL은 따로 한 줄에 표기, `baseVersionId`로 덮어쓰기 충돌 방지.
- **Vercel·Netlify·Cloudflare·here.now**: 사용자 콘텐츠는 PSL에 등록된 별도 도메인에 둡니다. vercel.app, netlify.app, workers.dev, here.now 모두 PSL에 있습니다(https://publicsuffix.org/list/public_suffix_list.dat).
- **Claude Code WebFetch의 특성**: 작은 모델이 요약해서 전달하고, 다른 호스트로의 리다이렉트는 따라가지 않고, localhost와 점 없는 호스트는 거부하며, 15분 동안 캐시합니다(https://code.claude.com/docs/en/tools-reference.md). 그래서 런북은 5KB 이하, 한 줄에 명령 하나, 원문 읽기 탈출구를 갖춰야 합니다.

## 3. Dandi 권장 설계

### (a) `/llms.txt`와 `/llms-full.txt`

**서빙 규칙**
- `GET /llms.txt`는 정규 호스트에서 리다이렉트 없이 200을 `text/markdown; charset=utf-8`로 반환합니다. `/.well-known/llms.txt`를 별칭으로 두고, 허브 응답에 `Link: </llms.txt>; rel="llms-txt"` 헤더를 붙입니다.
- 파일은 5KB 이하의 정적 파일이며 비밀값을 넣지 않습니다.
- 기존 `public/downloads/llms.txt`(교사 프로젝트용 템플릿)는 `AGENTS.md` 템플릿으로 이름을 바꿔 역할 혼동을 없앱니다.

### (b) CLI 브라우저 로그인 (device code 2단계)

**선택 이유.** v0.1은 RFC 8628 device code 흐름 하나로 통일합니다. Windows 포트 충돌이 없고, 클라우드 에이전트·SSH·WSL에서도 동작하며, 사람이 복사할 것이 없습니다. 루프백 PKCE는 v0.2에 사람이 TTY에서 직접 쓸 때를 위해 추가하고, Railway처럼 자동 전환합니다.

**엔드포인트 (Next.js route handler)**
- `POST /api/cli/device/start` 요청 본문 `{client:"claude-code", hostname, os}`, 응답 200 `{device_code, user_code:"WDJB-MJHT", verification_uri:"https://<hub>/device", verification_uri_complete:"https://<hub>/device?code=WDJB-MJHT", expires_in:600, interval:5}`
- `GET /device?code=…`: 교사 세션이 필수입니다. 미로그인이면 `/login?next=…`로 보냅니다. 승인보다 로그인을 먼저 하게 해서 피싱을 줄입니다(authenticate-then-initiate).
- `POST /api/cli/device/approve`: 세션 쿠키, Origin 검증, 요청 본문 `{user_code, decision:"approve"|"deny"}`. 감사 로그 `cli.device.approve`를 남기고 허브 알림을 보냅니다.
- `POST /api/cli/device/token` 요청 본문 `{device_code}`. 응답은 400 `{error:"authorization_pending"|"slow_down"|"access_denied"|"expired_token"}` 또는 200 `{token, token_id, expires_at, user:{name}}`입니다. 200은 한 번만 반환하고 그 즉시 device_code를 폐기합니다.

**코드 규칙**
- user_code는 `BCDFGHJKLMNPQRSTVWXZ`에서 뽑은 8자를 `XXXX-XXXX`로 표시하고, 입력은 대소문자를 구분하지 않습니다(RFC 8628 §6.1).
- device_code는 32바이트 base64url이며, DB에는 해시만 저장합니다(기존 `tokens.ts` hashSecret 재사용).
- 만료 600초, 1회용, 폴링 간격 5초, `slow_down`마다 5초 추가.
- 코드 입력은 사용자당 시간당 50회로 제한합니다(GitHub 기준). start는 IP당 분당 10회를 제안합니다.

**승인 화면**
- 큰 글씨의 코드와 "AI 대화창에 보이는 코드와 같나요?" 문구.
- 요청한 에이전트, 컴퓨터 이름, OS, IP, 요청 시각, 남은 시간, 권한("앱 올리기·허브 등록"), [승인]과 [거부] 버튼.
- 경고문: "직접 AI에게 Dandi 로그인을 시킨 경우에만 승인하세요. 웹사이트나 다른 사람이 이 코드를 보냈다면 거부하세요."

**CLI 동작**
- `dandi login`
  - 에이전트 또는 비TTY 환경에서는 start를 호출하고, 브라우저 열기를 시도한 뒤(실패는 무시) stdout에 JSON 1개를 출력하고 exit 0으로 끝납니다. 판별 기준은 `!process.stdin.isTTY` 또는 `CLAUDECODE`, `AI_AGENT`, `CODEX_SANDBOX`, `CODEX_CI`, `CODEX_THREAD_ID`, `CURSOR_AGENT`, `GEMINI_CLI` 환경변수입니다.
  - 사람이 TTY에서 실행하면 브라우저를 열고, URL과 코드를 따로 한 줄씩 출력한 뒤 그 자리에서 최대 10분 동안 폴링합니다.
- `dandi login --wait [--timeout 90]`: `~/.dandi/pending.json`(0600)에서 이어서 진행하고 기본 90초 안에 반환합니다. Claude Code Bash의 기본 제한이 2분이기 때문입니다. 아직 승인 전이면 exit 5와 같은 next_step을 돌려줍니다.
- 종료 코드: 0 성공, 1 기타, 4 로그인 필요, 5 대기 중, 6 거부, 7 만료, 20 번들 거부. 모든 오류 출력에 `다음 실행: npx -y dandi@latest login` 줄을 붙입니다.

```json
{"status":"pending","user_code":"WDJB-MJHT","verification_uri":"https://<hub>/device","verification_uri_complete":"https://<hub>/device?code=WDJB-MJHT","expires_in":600,"next_step":"npx -y dandi@latest login --wait --json","agent_next_steps":"Show verification_uri_complete and user_code to the user exactly as given, ask them to approve, then run next_step. Repeat next_step while status is pending."}
```

**토큰**
- 기존 `dd_cli_` 형식을 유지합니다. 이름은 `dandi CLI · <hostname> · <date>`, 범위는 `apps:write sites:deploy`, 만료는 90일입니다. v1에서 refresh 토큰 회전으로 바꿉니다.
- 저장 위치는 기존 `~/.dandi/config.json`이고 `DANDI_CONFIG_DIR`로 바꿀 수 있습니다. 파일은 0600, 디렉터리는 0700입니다. Windows에서는 chmod가 무시되므로 사용자 프로필 ACL에 의존합니다.
- `--json` 출력을 포함해 어떤 출력에도 토큰을 넣지 않습니다. 발급 목록과 폐기는 `/studio/cli`를 그대로 씁니다.

**CI 대체 경로.** 기존 `DANDI_TOKEN`과 `DANDI_HUB` 환경변수를 유지하고 `dandi login --token-stdin`을 추가합니다. 위치 인자 `login <token>`은 셸 기록과 프로세스 목록에 노출되므로 제거합니다. 토큰 발급 UI는 CI용으로만 남깁니다.

### (c) 허브 자체 정적 호스팅

**업로드 형식.** here.now 방식의 3단계입니다. zero-dep Node 18에는 zip을 만드는 기능이 없고, 서버에 압축 해제 의존성을 추가하지 않아도 됩니다.
1. `POST /api/sites/deploys` 요청 본문 `{site_id?, base_deploy_id?, files:[{path,size,sha256}]}`, 응답 `{deploy_id, site_id, upload:[{path,url}], finalize_url}`. 서버에 이미 있는 해시는 upload 목록에서 뺍니다.
2. `PUT /api/sites/deploys/<deploy_id>/files/<path>`로 원본 바이트를 보내면 서버가 크기와 sha256을 검증합니다.
3. `POST /api/sites/deploys/<deploy_id>/finalize`, 응답 `{site_id, deploy_id, preview_url, status:"preview"}`. `base_deploy_id`가 현재 배포와 다르면 409 `version_conflict`를 반환합니다.

- deploy가 `site_id`와 `last_deploy_id`를 `dandi.json`에 기록하고, publish는 이 값을 읽어 `url`을 자동으로 채웁니다.
- 웹 폴더 업로드(`webkitdirectory` 드래그)도 같은 API를 씁니다. 셸이 없거나 AI 도구를 무료 플랜으로 쓰는 교사를 위한 경로입니다.
- 파일은 `data/sites/<site_id>/<deploy_id>/…`에 불변으로 저장하고 현재 배포 포인터만 바꿉니다. 그래서 롤백이 쉽습니다.

**한도 (v0.1 제안, Cloudflare 임시 계정 한도 참고)**
- 합계 20MB, 파일 1,000개, 파일당 5MB. 계정당 사이트 20개, 시간당 배포 30회.
- 루트에 index.html 필수. 확장자는 허용 목록으로 제한합니다: html, css, js, mjs, json, txt, svg, png, jpg, jpeg, gif, webp, ico, woff2, mp3, mp4.
- 경로에 `..`, 절대경로, 역슬래시가 있으면 거부합니다. `node_modules/`, `.git/`, `.env*`는 CLI가 미리 제외합니다(Vercel deploy.sh 기준).
- `sk-`, `service_role`, `dd_cli_` 같은 비밀값 패턴이 있으면 exit 20과 `hint`로 거부합니다. 전화번호·주민번호 패턴은 기존 `pii.ts`로 찾아 경고만 합니다.

**URL과 격리**
- **로컬 프로토타입**: 허브는 `http://localhost:3000`, 사이트는 `http://<slug>.localhost:3000/`입니다. 기존 `src/proxy.ts`에 Host 헤더가 `*.localhost`이면 사이트 정적 핸들러로 보내는 규칙을 추가합니다.
  - 호스트가 다르므로 허브의 host-only 세션 쿠키가 사이트로 가지 않습니다.
  - 앱마다 origin이 달라 localStorage가 섞이지 않습니다. 교사 앱이 학생 데이터를 두는 곳이 localStorage이므로 중요합니다.
  - `*.localhost`의 루프백 해석은 Chrome·Edge 기준 예상이며 교사 PC에서는 확인하지 못했습니다.
- **운영**: 사이트는 허브와 다른 apex 도메인의 `https://<slug>-<4자>.<sites-domain>`에서 서빙하고, 와일드카드 TLS와 오브젝트 스토리지+CDN을 씁니다.
  - PSL 사설 섹션 등록을 신청합니다(Vercel 멀티테넌트 문서 절차: PR 제출과 `_psl` TXT 레코드).
  - 허브 쿠키는 `__Host-session; Secure; HttpOnly; Path=/; SameSite=Lax`로 발급하고 Domain 속성은 넣지 않습니다.
- **같은 origin 경로(`<hub>/s/<slug>/`)를 쓰지 않는 이유**: 업로드된 JS가 교사 세션으로 `/api/cli/*`나 관리 API를 호출하거나 다른 앱의 localStorage를 읽을 수 있습니다. `sites.<hub>` 같은 하위 도메인도 같은 site로 취급되어 쿠키 주입(cookie tossing)과 SameSite 우회 위험이 남습니다.
- **응답 헤더**: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Content-Security-Policy: frame-ancestors <hub>`. Set-Cookie는 금지하고, preview 상태에는 `X-Robots-Tag: noindex`를 붙입니다.
- **허브 안 미리보기**: `<iframe sandbox="allow-scripts allow-forms allow-same-origin">`을 씁니다. 사이트가 이미 다른 origin이라 `allow-same-origin`을 켜도 허브가 노출되지 않고, 끄면 localStorage를 쓰는 앱이 깨집니다.
- **익명 배포와 클레임**: v0.1에서는 넣지 않습니다. 학생 개인정보 노출과 피싱 호스팅 위험 때문입니다. Netlify도 클레임 기한을 1시간으로 줄이고 IP당 3개로 제한했습니다.

### (d) MCP: v0.1은 stdio(CLI 내장), v0.2는 원격 HTTP + OAuth

**판단 근거**
- 원격 MCP를 하려면 OAuth 인가 서버 전체를 만들어야 합니다. PRM, AS 메타데이터, authorize·token 엔드포인트, PKCE, CIMD와 DCR, 동의 화면, refresh 회전, 클라이언트별 리다이렉트 허용 목록이 모두 필요합니다.
- claude.ai와 ChatGPT는 인터넷의 공개 HTTPS 서버에만 접속합니다(Anthropic egress 160.79.104.0/21, https://claude.com/docs/connectors/building/authentication). 따라서 localhost 프로토타입에서는 쓸 수 없습니다.
- stdio는 (b)의 로그인 토큰을 그대로 쓰고 로컬 폴더를 경로로 읽을 수 있습니다. Claude Desktop에서도 "이 폴더 올려줘"가 됩니다. 코딩 에이전트는 CLI만으로 충분합니다. 힉스필드도 코딩 에이전트에는 CLI를 권합니다.
- 구현: zero-dep을 유지하려면 최소 JSON-RPC(initialize, tools/list, tools/call, ping, 2026-07-28 클라이언트용 server/discover)를 직접 구현합니다. 부담스러우면 CLI에만 `@modelcontextprotocol/server@^2`를 추가합니다. 검증은 `npx @modelcontextprotocol/inspector@latest`로 합니다.

**도구 목록 (6개)**
- `dandi_whoami` (readOnlyHint)
- `dandi_login`: 승인 URL과 코드를 반환합니다. 채팅 화면에 링크가 표시됩니다.
- `dandi_deploy_folder {path, site_id?}`: stdio 전용.
- `dandi_deploy_files {files:[{path, content, encoding}], site_id?}`: 합계 1MB 이하. 셸이 없는 클라이언트용입니다.
- `dandi_publish_app {site_id, title, description, schoolLevels, category, privacyCheck}`: 도구 설명에 "교사가 5문항을 확인하기 전에는 호출 금지"를 명시합니다.
- `dandi_list_my_apps` (readOnlyHint): 배포 상태를 포함합니다.

**v0.2 구현 체크리스트**
- 라이브러리: `mcp-handler@^2`(2.2.0) + `@modelcontextprotocol/server@^2` + `zod@^4`, `withMcpAuth` 사용.
- 401 응답: `WWW-Authenticate: Bearer resource_metadata="https://<hub>/.well-known/oauth-protected-resource/mcp"`.
- PRM은 두 well-known 경로 모두에 둡니다. `resource`는 `https://<hub>/mcp`와 정확히 같아야 하고, `authorization_servers`에는 한 개만 넣습니다. Claude는 첫 항목만 쓰기 때문입니다.
- AS 메타데이터: S256, `token_endpoint_auth_methods_supported`에 `none`, `client_id_metadata_document_supported:true`, `registration_endpoint`(Cursor·VS Code용 DCR), `authorization_response_iss_parameter_supported:true`, `device_authorization_endpoint`((b)의 흐름을 이쪽으로 옮김).
- 리다이렉트 허용 목록:
  - Claude: `https://claude.ai/api/mcp/auth_callback`
  - Claude Code: localhost와 127.0.0.1의 `/callback`, 포트 무관
  - Codex: `http://127.0.0.1:<port>/callback/<id>`
  - ChatGPT: `https://chatgpt.com/connector_platform_oauth_redirect`, `https://chatgpt.com/connector/oauth/{id}`
  - Cursor: `https://www.cursor.com/agents/mcp/oauth/callback`, `http://localhost:8787/callback`
  - VS Code: `http://127.0.0.1:33418`, `https://vscode.dev/redirect`
- token 엔드포인트는 form-urlencoded를 받고, 만료된 refresh 토큰에는 `invalid_grant`를 반환하고, refresh 토큰을 회전하고, 10초 안에 응답해야 합니다.
- `/.well-known`, `/oauth`, `/mcp` 앞에 봇 차단(WAF)을 두지 않습니다.
- 인가 서버 후보는 better-auth 1.7.6 + `@better-auth/mcp` + `@better-auth/cimd` + `oauthDeviceAuthorization()`입니다. 2025년 방식 클라이언트를 막지 않도록 `legacy: "reject"`는 쓰지 않습니다.

## 4. 리스크와 미결 사항

**리스크**
1. **로컬 프로토타입에서는 링크 흐름을 그대로 시험할 수 없습니다.** WebFetch는 localhost와 점 없는 호스트를 거부하고, claude.ai·ChatGPT는 공개 HTTPS에만 접속합니다. 시연용으로 공개 HTTPS(터널 또는 스테이징 서버)를 준비하고, 로컬에서는 `dandi guide`로 대신합니다.
2. **device code 피싱.** Storm-2372 사례와 2026년 4월 AI 자동화 캠페인이 있습니다(https://www.microsoft.com/en-us/security/blog/2026/04/06/ai-enabled-device-code-phishing-campaign-april-2026/). 로그인 후 승인, 코드 대조, 10분 만료, 1회용, 최소 권한, 승인 알림, 폐기 UI로 대응합니다.
3. **WebFetch 요약으로 명령이 바뀔 수 있습니다.** 런북을 5KB 이하로 두고 한 줄에 명령 하나만 쓰며, `guide` 탈출구를 둡니다. WebFetch는 리다이렉트를 따라가지 않으므로 handoff 문구에는 정규 호스트만 씁니다.
4. **사용자 콘텐츠 호스팅 책임.** 피싱·스팸 호스팅, Safe Browsing 등재, 신고·삭제 절차 문제가 있습니다. PSL 등록에 걸리는 기간은 확인하지 못했습니다.
5. **교육청 가이드라인 미확정(PRD Q2).** 정적 호스팅이라도 앱 코드가 외부로 데이터를 보낼 수 있으므로 셀프점검을 게시 조건으로 유지합니다.
6. **프로토콜 세대 차이.** MCP 현행 스펙은 2026-07-28이지만 Claude는 2025-03-26~2025-11-25 인가 스펙을 따릅니다. 서버는 두 세대를 모두 지원해야 합니다.
7. **요금제 제약.**
   - Claude 무료 플랜의 커스텀 커넥터 한도는 문서마다 다릅니다. claude.com 문서는 1개라고 하고, Vercel 문서는 Pro 이상이라고 합니다.
   - ChatGPT 개발자 모드는 Plus 이상에서만 쓸 수 있고, 학교 관리자가 끌 수 있습니다.
8. **Windows 환경.** PowerShell에서 `curl`은 Invoke-WebRequest 별칭이므로 `curl.exe`를 써야 합니다. JSON 인자 인용도 문제가 되므로 입력은 `dandi.json` 파일로 받습니다.

**미결 사항**
- **npm 패키지 이름 `dandi`를 쓸 수 있는지 확인하지 못했습니다.** 대안은 `@<org>/dandi`입니다. 프로토타입 단계에서는 허브가 tarball을 제공하는 `npx -y https://<hub>/downloads/dandi.tgz` 방식을 쓸 수 있지만, 동작 검증이 필요합니다.

## 2. Dandi 권장 설계

### (a) 프로젝트 API 키 (Edge Impulse 방식)

**데이터 모델.** 한도와 모델 정책은 프로젝트에 두고, 키는 인증 수단으로만 씁니다. Gemini가 "per project, not per API key"를 원칙으로 두는 것과 같습니다.

```ts
type Project = {
  id: string; name: string; ownerUserId: string; collaboratorIds: string[];
  appIds: string[];                        // F-04 미니앱과 1:N 연결, dandi.json에 projectId 기록
  monthlyTokenBudget: number;              // 필수 ('한도 없음' 프로젝트는 만들지 않음)
  alertAtPct: number;                      // 기본 80 (soft 알림), 100%에서 hard 차단
  rpm: number;                             // rate limit도 프로젝트 단위 (키를 늘려 한도를 넘는 우회 차단)
  modelPolicy: { mode: "allow_list" | "deny_list"; modelIds: string[] };
  status: "active" | "archived";           // 보관하면 키 전체를 비활성화
  createdAt: string;
};
type ProjectApiKey = {
  id: string; projectId: string; name: string;               // 예: "3반 퀴즈앱 서버"
  role: "admin" | "inference" | "readonly";                  // 기본값 inference
  kind: "secret" | "publishable";                            // dd_sk_ / dd_pk_
  prefix: string; last4: string; hash: string;               // 원문은 저장하지 않음
  allowedOrigins?: string[]; keyBudget?: number;             // publishable 키 전용
  createdByUserId: string; createdAt: string; expiresAt: string | null;
  lastUsedAt: string | null; lastUsedIp: string | null;
  revokedAt: string | null;                                  // 비활성화(복구 가능)
  deletedAt: string | null;                                  // 삭제(영구)
};
// UsageRecord에 projectId, keyId를 추가해 프로젝트별·키별로 집계
```

- **역할:** `inference`는 게이트웨이 호출만 할 수 있습니다. `readonly`는 사용량과 설정을 조회만 합니다. `admin`은 CLI나 CI에서 키·한도 관리 API를 호출할 수 있습니다. Edge Impulse의 4단계 역할을 3단계로 줄인 것입니다. development 키처럼 원문을 다시 보여 주는 키는 두지 않습니다.
- **실효 모델:** 교육청 F-23에서 `allowed`인 모델과 프로젝트 `modelPolicy`의 교집합입니다. `pending`과 `blocked`는 늘 제외합니다(OpenAI allow_list/deny_list, OpenRouter 교집합 방식).
- **한도 검사 순서:** 키 만료·비활성화면 401 → 프로젝트 보관 상태면 403 → 모델 불허면 403 `model_not_allowed` → 프로젝트 예산 초과면 429 `project_quota_exceeded` → 교사 전체 상한(F-28) 초과면 429 `teacher_quota_exceeded` → 공개 키 예산 초과면 429 `key_quota_exceeded`. 예상 토큰을 먼저 예약하고 응답 후 정산합니다(OpenAI는 "Enforcement is not instantaneous"라고 명시).
- **UI:** `/studio/projects/[id]`에 탭 5개(개요 · **키** · 사용량 · 모델 · 설정)를 둡니다. 키 탭에서 `+ 새 API 키`를 누르면 이름, 역할, 만료 프리셋(수업 1회 3시간 / 1일 / 7일 / 30일 / 학기 말 / 없음)을 고릅니다. 원문은 모달에서 **한 번만** 보여 주고 "다시 볼 수 없습니다"라는 안내와 복사 버튼을 둡니다. 목록 열은 이름, 역할, 힌트(`dd_sk_ab12…9f3c`), 만든 사람, 만든 날짜, 마지막 사용(시각·IP), 만료, 상태, [비활성화]·[삭제]입니다. 만료 7일 전과 1일 전에는 배지를 띄웁니다(Anthropic의 메일 알림 방식).
- **게이트웨이 인증:** 지금처럼 `Authorization: Bearer dd_sk_...`를 유지하고, Edge Impulse식 `x-api-key: dd_sk_...`도 받습니다. 키만 있으면 프로젝트가 정해지므로 projectId는 따로 보내지 않습니다. 모든 응답에 `x-dandi-project-id`를 붙입니다(Anthropic `anthropic-workspace-id` 방식). 키·한도·모델 관리는 교사 세션이나 CLI 토큰(F-17), `admin` 키로만 할 수 있게 하고 `inference` 키로는 막습니다.
- **기존 교사별 키 이전(무중단):**
  1. 교사마다 "기본 프로젝트"를 만들고, 기존 활성 키에 `projectId`를 채우고, `monthlyQuota`를 `Project.monthlyTokenBudget`으로 옮기고, 과거 `usage`에도 projectId를 채웁니다. 해시가 그대로이므로 기존 키는 계속 동작합니다.
  2. `issueKey(user)`를 `createProjectKey(projectId, {name, role, expiresAt})`로 바꾸고, 기존 키 자동 폐기를 없앱니다(새 키 → 교체 → 옛 키 비활성화 순서로 겹쳐서 교체).
  3. `authenticateKey`가 `{project, key, owner}`를 돌려주게 하고, `sumUsage`에 `projectId` 필터를 추가합니다.
  4. F-27 감사 로그에 `apikey.create`, `apikey.disable`, `apikey.delete`, `project.budget.update`, `project.models.update`를 남깁니다.
- **미니앱에서 AI를 안전하게 호출하는 방법:**
  - **A. 서버 프록시(기본값, 권장):** 미니앱의 서버 함수(예: Vercel `/api/ai`)가 환경변수 `DANDI_PROJECT_KEY`로 게이트웨이를 부릅니다. 템플릿(F-09)과 `dandi init`에 이 구조를 넣습니다.
  - **B. 공개 키(정적 미니앱용):** `dd_pk_` 키에 `allowedOrigins`, 작은 전용 예산, 낮은 rpm, 모델 1개 고정을 붙입니다. Origin은 위조할 수 있으므로 실제 방어선은 **전용 예산**입니다(Supabase도 "an attacker can still use the key from other tools"라고 명시).
  - **C. 단기 토큰(이후 단계):** 서버가 1회용·30분·모델 고정 토큰을 발급합니다(Gemini ephemeral token 방식).
  - 게이트웨이는 `dd_sk_` 요청에 `Origin`이나 `Sec-Fetch-Mode` 같은 브라우저 신호가 있으면 401로 거부합니다. 교사가 HTML에 키를 붙여 넣는 사고를 바로 드러내기 위해서입니다.

### (b) 스킬 레지스트리 (skills.sh 방식)

**원칙:** 허브 자체를 설치 소스로 씁니다. Next.js가 Discovery v0.2.0 인덱스를 직접 제공하면, 교사는 GitHub 계정이 없어도 명령 한 줄로 설치할 수 있습니다. skills CLI 소스에서 digest 검증까지 확인했습니다.

```text
app/.well-known/agent-skills/[[...path]]/route.ts   # v0.2.0 index.json + 스킬 zip
app/.well-known/skills/[[...path]]/route.ts         # 구 경로 (CLI 폴백)
app/packs/[id]/.well-known/agent-skills/...         # 팩: CLI가 "path-relative first"로 먼저 찾음
index.json 항목: {"name","type":"archive","description","url","digest":"sha256:<64 hex>"}
$schema: https://schemas.agentskills.io/discovery/0.2.0/schema.json
```

**설치 명령.** 상세 페이지의 도구별 탭에서 복사합니다.

```bash
# Claude Code + Cursor + Codex 동시 설치 (프로젝트 범위)
npx skills add https://<dandi-domain> --skill <name> -a claude-code -a cursor -a codex --copy
# 전역 설치 / 팩 설치
npx skills add https://<dandi-domain> --skill <name> -a claude-code -g --copy
npx skills add https://<dandi-domain>/packs/new-teacher-starter
# 승인된 공개 스킬의 GitHub 미러 (저장소 이름은 제안)
npx skills add codekorea/dandi-skills --skill <name>
/plugin marketplace add codekorea/dandi-skills     # Claude Code 세션 안에서
/plugin install dandi-kit@<marketplace-name>
# claude.ai: Customize > Skills > "+" > "Upload a skill" (zip 다운로드 버튼 제공)
```

`--copy`는 학교 Windows PC에서 심볼릭 링크를 만들지 못하는 경우를 대비한 추론이며, 실제로 테스트하지는 않았습니다. 설치 경로를 허브가 직접 정하지 말고 CLI의 `-a`에 맡깁니다(Codex 전역 경로가 문서마다 다르기 때문).

- **게시 흐름:** 웹 zip 업로드 또는 `dandi skill init <name>`, `dandi skill publish ./<dir>`로 올립니다. 이후 서버 검증 → 자동 스캔 → `pending` → (조건에 따라 사람 검토) → `approved` 순서로 진행되고, 승인되면 index에 반영하고 설치 수를 집계합니다. 게시할 때마다 새 버전(`metadata.version`, semver)과 digest를 만들고 이전 버전도 계속 받을 수 있게 합니다. 파일을 덮어쓰면 교사들이 설치한 스킬이 모르는 사이에 바뀝니다.
- **SKILL.md 검증:**
  - `name`은 `^[a-z0-9]+(-[a-z0-9]+)*$` 형식, 64자 이내, 폴더 이름과 같아야 합니다. 한글은 쓸 수 없으므로 한국어 제목은 `metadata.title`에 둡니다.
  - `description`은 1~1024자이고 한국어와 영어 트리거 키워드를 함께 넣게 권장합니다.
  - `compatibility`는 500자 이내이고, `license`는 허브에서 필수로 받습니다.
  - SKILL.md는 500줄 이하를 권장합니다. 파일당 2 MB, 바이너리는 `assets/`에만 허용하고, `..` 경로와 스킬 밖을 가리키는 심볼릭 링크는 거부합니다.
- **안전 검토:**
  1. 정적 규칙으로 `curl|bash`, base64·유니코드 난독화, 암호가 걸린 zip, env·자격증명 파일 읽기, `!` 명령, `hooks`, `allowed-tools: Bash(*)`, 허용되지 않은 도메인 호출을 잡습니다.
  2. 압축을 푼 스킬에 `uvx mcp-scan@latest --skills`를 돌립니다.
  3. `scripts/`, `hooks`, `!` 명령 중 하나라도 있으면 **사람 검토를 필수**로 하고, 프롬프트만 있는 스킬은 빠르게 통과시킵니다.
  4. 학생 이름·학번·연락처·주민번호 패턴과 API 키가 들어 있으면 차단합니다(F-13, F-16과 연계).
  5. 신고 버튼을 두고 N건이 쌓이면 자동으로 숨깁니다(F-26).
  6. 새 버전을 올릴 때마다 다시 검토합니다.
- **페이지 구조:**
  - `/skills`: 검색, 과목·학교급·호환 도구 필터, 전체 / 이번 주 / 급상승 탭. 순위는 서버 다운로드 수로 매기므로 클라이언트 텔레메트리가 필요 없습니다. 카드에는 한국어 제목, `name`, 설치 수, "스크립트 포함"·"검토 완료" 배지를 둡니다.
  - `/skills/[name]`: 설치 명령 복사 박스, 렌더링한 SKILL.md, 파일 트리, 버전 목록과 버전 고정 zip URL, 라이선스, 호환 도구, 관련 스킬, 신고 버튼.
  - `/skills/new`, `/packs/[id]`.
- **CLI·MCP 연동:**
  - `dandi skill add <name> [--agent claude-code,cursor,codex] [-g]`는 내부에서 `npx skills add https://<hub> --skill <name> ... --copy`를 호출합니다. 학교용 안내에는 `DISABLE_TELEMETRY=1`을 넣습니다.
  - 공식 플러그인(dandi-deploy, llms-txt-init, student-pii-check, `.mcp.json`)을 제공합니다.
  - 허브 MCP 도구(`search_skills`, `get_skill`)는 위키독스 MCP 사례를 참고한 제안입니다.
- **초기 스킬 후보:** `parent-letter-writer`, `lesson-plan-rubric`, `student-pii-check`, `textbook-selection-hwpx`(기존 HWPX 스킬의 라이선스를 확인한 뒤 진행), `dandi-deploy`. 스킬 안에서는 프로젝트 키를 `.env`의 `DANDI_PROJECT_KEY`로 읽고, 스킬 파일에 직접 넣지 않습니다.

### (c) 전자책 서가

**v0.1(최소 범위)**

- **데이터 모델:** `Book { id, title, summary, authorName, ownerUserId, coverUrl?, kind: "webbook"|"pdf", baseUrl?, fileId?, level, license, visibility: "public"|"teachers", containsThirdPartyWorks, toc[{title,href,depth}], pageCount, viewCount, updatedAt }`
- **웹북은 URL로 등록합니다.** 업로드 없이 이미 올라가 있는 사이트(GitHub Pages, Vercel)를 등록하며, F-04 미니앱 등록과 같은 방식입니다. 서버가 `sitemap.xml`과 `search/search_index.json`을 가져와 제목, 장 목록, 페이지 수, lastmod를 자동으로 채우고, 교사가 미리보기를 확인한 뒤 등록합니다. 생성기와 상관없이 동작하므로 나중에 Zensical로 바꿔도 영향이 없습니다. 빌드한 `site/`를 Next.js `public/`에 복사하거나 rewrites로 같은 출처에 프록시하는 방식은 trailing slash와 디렉터리 인덱스 문제 때문에 v0.1에서는 쓰지 않습니다.
- **웹북 리더(`/books/[id]`):** 상단 바(← 서가, 책 제목, '새 창에서 열기'), 허브가 그리는 목차 패널, 본문 iframe으로 구성합니다. 이어 읽기는 '허브 목차에서 마지막으로 연 장'을 localStorage(try/catch)에 저장하는 근사치라고 화면에 명시합니다. 교차 출처 iframe 안에서의 이동은 부모 페이지가 읽을 수 없기 때문입니다.
- **PDF 리더:** 자료실(F-08) 파일에 '서가에 올리기'를 붙입니다. `react-pdf`를 dynamic import하고 SSR을 끕니다. `pdfjs-dist/cmaps`를 `public/cmaps`로 복사하고 `options={{ cMapUrl: '/cmaps/' }}`를 지정합니다. 기능은 쪽 이동, 확대, outline 목차, 이어 읽기 쪽 저장, '원본 열기' 링크입니다. 브라우저 안에서 열람할 수 있도록 `Content-Disposition: inline`으로 응답하는 `/api/files/[id]/view`를 새로 만듭니다. iOS Safari에서 iframe·embed 안의 PDF가 첫 페이지만 보인다는 커뮤니티 보고가 있으므로, 브라우저 내장 뷰어를 임베드하는 방식에는 기대지 않습니다.
- **저작권 게이트:** '제3자 저작물 포함'에 체크한 책은 공개 서가에 올릴 수 없고 교사 전용으로 강제하며, 경고 문구를 자동으로 붙입니다(저작권법 제25조 제12항, 시행령 제9조, [근거](https://easylaw.go.kr/CSP/CnpClsMain.laf?popMenu=ov&csmSeq=695&ccfNo=3&cciNo=2&cnpClsNo=6)).
- **서가 목록(`/books`):** 카드에 표지, 저자, 형식 배지, 학교급(`LevelOrAll` 재사용), 수정일을 보여 주고, 학교급·형식 필터와 최신·열람 수 정렬을 둡니다. 첫 번째 시드는 코드코리아 웹북입니다.

**이후 단계:** 서가 통합 검색(`search_index` 항목을 허브 인덱스에 넣음), 로그인 기반 진도·책갈피 동기화, 클래스 참여 코드(위키독스 8자리 방식), 열람자 워터마크, Git 연동 집필(`dandi book publish`, webhook), EPUB(foliate-js를 submodule로 넣거나 Thorium Web + Go-Toolkit), 하이라이트·메모, 오프라인 ZIP(Material `offline`을 별도로 빌드), HWP 미리보기(rhwp), 판매·ISBN.

## 4. 리스크·미결 사항

**리스크**

- **키:**
  - 교사가 프로젝트를 여러 개 만들어 무상 한도를 늘릴 수 있습니다. 교사 전체 상한(F-28)을 겹쳐서 검사하고 프로젝트 수에도 상한을 두어 막습니다.
  - hard limit은 즉시 걸리지 않습니다. 예약 후 정산하는 방식으로 동기 차감합니다.
  - 공개 키의 Origin 제한은 위조할 수 있습니다.
  - 만료 알림이 없으면 수업 중에 미니앱이 멈출 수 있습니다.
- **스킬:**
  - Snyk ToxicSkills(2026-02-05) 조사에서 3,984개 중 13.4%에 치명적 문제가 있었고 악성 페이로드 76건이 확인됐습니다.
  - well-known 엔드포인트를 읽지 못하는 CLI 버그 [#985](https://github.com/vercel-labs/skills/issues/985)가 열려 있습니다. digest는 CRLF나 재압축으로 바이트가 1개만 달라져도 실패합니다.
  - 허브에만 있는 스킬은 skills.sh 감사를 받지 못합니다. 리더보드에 노출되는지는 확인 못 함입니다.
  - Anthropic의 docx·pdf·pptx·xlsx 스킬은 "source-available"이라 다시 호스팅하면 안 됩니다.
- **전자책:**
  - 교사 자료에 제3자 저작물이 섞일 수 있습니다(제25조).
  - 웹에서는 DRM을 할 수 없습니다(LCP FAQ). 텍스트 선택 차단은 접근성만 해칩니다.
  - Material for MkDocs 지원은 2027-05-05에 끝나고, 후속인 Zensical은 v0.0.66으로 1.0 전입니다.
  - 위키독스는 봇 요청에 403을 돌려주므로 외부 링크로만 연결합니다.

**확인 못 한 항목**

OpenAI 키의 1회 표시와 권한 3종(Help Center 403), Edge Impulse `wladmin` 역할의 의미와 Keys 탭 폐기 버튼 이름, Anthropic·Gemini의 프로젝트별 모델 allowlist, Windows에서 `--copy`가 필요한지, 학교망에서 외부 폰트·CDN이 차단되는지, 밀리의서재 공식 기능.

**결정이 필요한 사항(코드코리아·교육청)**

1. 프로젝트와 미니앱을 1:1로 할지 1:N으로 할지, 교사가 전근·퇴직할 때 프로젝트 소유권을 어떻게 이전할지
2. 기본 프로젝트 예산과 교사 전체 상한의 기본값, 공개 키를 허용할지
3. 스킬을 게시할 수 있는 사람(교사 전원 또는 인증 교사)과 검토 주체(교육청 또는 코드코리아), GitHub 미러 조직 이름
4. 서가에 코드코리아 유료 교재를 넣을지와 학생 열람을 어디까지 허용할지(클래스 코드 도입 시점)
