# DESIGN.md — 교사 미니앱 디자인 명세 (Dandi 예시)

> 이 파일을 프로젝트 루트에 두고 AI 코딩 도구에 "화면을 만들거나 고칠 때 DESIGN.md를 따르라"고 지시하십시오.
> 값은 학교·앱 성격에 맞게 바꾸어도 됩니다. 바꾼 값은 이 파일에 먼저 적고 코드에 반영합니다.

## 1. 원칙

1. **한 화면에 한 가지 일.** 첫 화면에서 가장 자주 하는 동작 하나가 바로 보여야 합니다.
2. **휴대전화 먼저.** 360px 너비에서 먼저 만들고, 넓은 화면은 여백과 열만 늘립니다.
3. **색보다 글자.** 상태(정답/오답, 출석/결석)는 색과 글자를 함께 써서 구분합니다.
4. **꾸밈보다 읽기.** 그림자, 그라데이션, 움직임은 쓰지 않거나 최소로 씁니다.

## 2. 색 (디자인 토큰)

CSS 변수로 정의하고, 코드에서는 변수 이름만 씁니다. 다크 모드는 `prefers-color-scheme: dark`에서 같은 이름의 값을 바꿉니다.

| 토큰 | 라이트 | 다크 | 쓰임 |
|---|---|---|---|
| `--bg` | `#ffffff` | `#121212` | 페이지 배경 |
| `--fg` | `#1a1a1a` | `#e8e8e8` | 본문 글자 |
| `--muted` | `#666666` | `#9a9a9a` | 보조 설명 |
| `--line` | `#dddddd` | `#3a3a3a` | 테두리, 구분선 |
| `--accent` | `#0b57d0` | `#8ab4f8` | 주요 버튼, 링크 (강조색은 이것 하나) |
| `--ok` | `#1b7f3b` | `#81c995` | 성공, 정답 |
| `--danger` | `#c62828` | `#f28b82` | 오류, 삭제 |
| `--warn-bg` / `--warn-fg` | `#fff4e5` / `#8a4b00` | `#3a2a10` / `#ffcc80` | 개인정보 경고, 주의 안내 |

- 글자와 배경의 명도 대비는 4.5:1 이상을 유지합니다.
- 새 색이 필요하면 토큰을 추가하고 이 표에 적습니다. 코드에 색 값을 직접 쓰지 않습니다.

## 3. 글꼴

- 글꼴: `system-ui, -apple-system, "Segoe UI", "Malgun Gothic", "Apple SD Gothic Neo", sans-serif`
  외부 웹 글꼴(CDN)은 불러오지 않습니다. 학교망에서 느리거나 막힐 수 있습니다.
- 크기: 본문 16px, 보조 14px, 소제목 18px, 제목 22px. 이 네 가지만 씁니다.
- 줄 간격: 본문 1.55, 문서 미리보기 1.6
- 굵기: 보통 400, 강조 600~700
- 숫자·코드: `ui-monospace, Consolas, monospace`

## 4. 간격과 배치

- 간격 단위는 4px 배수: 4, 8, 12, 16, 24, 32
- 페이지 좌우 여백 16px, 본문 최대 너비 720px(표·문서가 있는 화면은 960px)
- 입력 양식은 한 줄에 한 칸을 기본으로 하고, 넓은 화면에서만 2열로 둡니다.
- 가로 스크롤이 생기면 안 됩니다. 넓은 표는 표만 가로로 스크롤되게 감쌉니다.

## 5. 컴포넌트

| 컴포넌트 | 규칙 |
|---|---|
| 버튼 | 높이 44px 이상, 모서리 4px. 주요 버튼(배경 `--accent`)은 화면당 하나. 나머지는 테두리 버튼 |
| 입력칸 | 위에 라벨(`<label>`)을 둡니다. 자리 표시 글자(placeholder)는 예시만 적고 라벨을 대신하지 않습니다 |
| 목록 | 항목 사이 1px 구분선, 위아래 여백 10px |
| 표 | 머리글 굵게, 행 구분선만. 세로선은 쓰지 않습니다 |
| 안내·경고 | `--warn-bg` 배경 상자 한 줄. 개인정보 관련 안내는 항상 이 상자를 씁니다 |
| 빈 상태 | "아직 항목이 없습니다. 위에서 추가하십시오."처럼 다음 행동을 알려 줍니다 |
| 오류 | 입력칸 바로 아래에 `--danger` 글자로, 무엇을 고치면 되는지 적습니다 |

## 6. 문구

- 존댓말(합니다체)로 씁니다. 안내는 "~하십시오", 결과는 "~했습니다".
- 느낌표, 이모지, 과장 표현("완벽한", "혁신적인")을 쓰지 않습니다.
- 버튼 글자는 동사로 끝냅니다: "추가", "복사", "등록" (명사형 동작어도 허용).
- 학생·학부모가 보는 화면에는 전문 용어(localStorage, API)를 쓰지 않습니다.

## 7. 접근성

- 모든 입력칸에 라벨, 모든 아이콘 버튼에 `aria-label`
- 키보드만으로 모든 기능을 쓸 수 있어야 합니다(탭 순서 = 화면 순서).
- 결과·오류 메시지는 `role="status"` 또는 `role="alert"`로 알립니다.
- 글자 크기를 200%로 키워도 내용이 잘리지 않아야 합니다.

## 8. 해야 할 것 / 하지 말 것

**해야 할 것**

- 첫 화면에 앱 이름과 한 줄 설명, 그리고 개인정보 처리 방식 한 줄("입력 내용은 이 기기에만 저장됩니다")
- 저장·복사·삭제 뒤에 결과 메시지 표시
- 삭제처럼 되돌릴 수 없는 동작은 버튼 글자에 대상을 적기("오늘 기록 초기화")

**하지 말 것**

- 학생 이름·연락처 입력칸 만들기
- 외부 글꼴·아이콘 CDN, 분석(추적) 스크립트 넣기
- 색만으로 상태 구분하기, 회색 글자를 본문에 쓰기
- 팝업(alert, confirm)으로 흐름 끊기, 자동 재생 소리·움직임
- 화면마다 다른 버튼 모양 만들기
